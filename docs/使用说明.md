# 维度之家（Dimension Home）使用说明

> Minecraft **Forge 1.20.1** MOD · 版本 **1.0.0** · MOD ID `dimensionhome`
>
> 一个属于你自己的虚空空岛维度：用平滑石搭一扇门，点燃它，就能回到固定的空岛落脚点；
> 再走回来时，你会回到原来那个世界的**原来那扇门**旁边。

> 📦 **只想下载 jar？** 到本仓库的
> [Releases](https://github.com/GNX001/dimensionhome/releases) 页下载
> `dimensionhome-1.0.0.jar`；自行构建则产物在 `build\libs\`。

---

## 一、这是什么

主世界、下界、末地——任何地方都能搭一扇**平滑石**门。点燃后进入一个纯虚空的空岛维度
「维度之家：空岛」。空岛里只有一块**与门等宽**的落脚平台和**唯一一扇**返回门，除此之外空无一物。

从空岛走回那扇门，你会被精准送回**出发的那个维度、出发的那扇门**旁边，
而不是被丢到某个默认出生点。

### 核心特性一览

| 特性 | 说明 |
| --- | --- |
| 坐标缩放 | **1:1**（主世界走 100 格，空岛也是 100 格） |
| 门颜色 | **金色 `#FFD700`**（门方块、传送时屏幕蒙版、粒子三处统一为金色） |
| 昼夜 | **有**昼夜交替，与主世界同步流逝 |
| 天空光照 | 有（`has_skylight = true`） |
| 地形 | **纯虚空**，不生成浮空岛、矿物、树木、结构、村庄 |
| 袭击 | **不触发**袭击（`has_raids = false`），但怪物生成规则与主世界一致 |
| 床 | 可以睡觉（`bed_works = true`） |
| 重生锚 | 不可用（`respawn_anchor_works = false`） |
| 维度范围 | Y 从 **0** 到 **256** |
| 返回规则 | 回到**原维度 + 原门位置**（主世界/下界/末地通用） |
| 空岛内点火 | 平台周围 **12 格范围内可以自由点燃**任意形状的门，但**同时只能有一扇**；范围外禁止 |
| 首门形状 | 空岛第一扇门**完全复刻**你第一次进门那扇门的形状与朝向 |
| 拆门兜底 | 门被拆掉也不会被困：区域内重新搭门点燃即可，另有 `/dimensionhome home` 命令逃生 |

## 三、安装

### 3.1 前置要求

| 项目 | 要求 |
| --- | --- |
| Minecraft | **1.20.1** |
| Forge | **47.4.26**（或任何 47.x 版本） |
| Java | **17** |
| **必需前置 MOD** | **Custom Portal API Reforged 1.0.2**（MOD ID：`cpapireforged`） |

> ✅ **Forge 版本兼容性已实测**：本 MOD 在 **47.4.10** 与 **47.4.26** 上均完整验证通过
> （维度注册、地标生成、传送链路、点燃拦截全部通过测试）。任何 47.x 版本均可使用。


> ⚠️ **Custom Portal API Reforged 是本 MOD 的硬性前置**，缺少它游戏会直接崩溃
> （报 `Missing or unsupported mandatory dependencies`）。版本必须 **≥ 1.0.2**，
> 且必须与本 MOD **同时**放进 `mods\`。详见第七章「常见问题」第一条。
>
> 📌 这条要求已经写进 jar 里面（不用翻本文档也能看到）：
> - 游戏内「Mods」列表里，本 MOD 的说明文字第一行就是前置要求；
> - jar 内的 `README.txt` 是完整中文说明，含前置、安装、玩法、规则、FAQ；
> - `META-INF\mods.toml` 里 `modId="cpapireforged"`、`mandatory=true`、`versionRange="[1.0.2,)"`
>   —— 这是 Forge 的硬性依赖声明，缺前置时游戏在加载阶段就会拒绝启动。

### 3.2 客户端（单人游戏）

1. 装好 Forge 1.20.1。
2. 打开游戏目录下的 `mods\` 文件夹（没有就新建）。
   单人整合包通常在 `.minecraft\mods\`；用启动器做了版本隔离时，
   则在 `.minecraft\versions\<版本名>\mods\`。
3. 把下面两个 jar 都放进去：
   - `dimensionhome-1.0.0.jar`（自行构建则位于 `build\libs\`）
   - `customportalapi-reforged-1.0.2.jar`
4. 启动游戏，主菜单 → Mods 列表里应能看到 **Dimension Home** 与 **Custom Portal API ReForged**。

> 💡 **怎么确认装对了**：游戏目录下 `mods\` 里应该正好有上面两个文件；
> 进游戏后 Mods 列表里两个都在，且 **Dimension Home** 的说明文字第一行写着「必需前置 MOD」。

### 3.3 服务器

1. 服务器根目录下建 `mods\` 文件夹。
2. 把上面两个 jar 放进去。
3. 启动服务器。控制台应出现类似日志：

```
[dimensionhome/]: 维度之家：空岛地标已就位 —— 落脚平台 y=99（与门等宽，沿门法线前后各延伸 2 格）与唯一返回门（轴向=X，内腔 2x3）
```

看到这行就说明空岛平台和那一扇门已经自动建好了。

## 四、怎么玩

### 4.1 第一步：搭一扇平滑石门

**平滑石（Smooth Stone）**的获取方式：把**石头**放进熔炉烧一下，就得到平滑石。

在你想开门的地方，用平滑石搭一个**中间空 2 格宽、3 格高的门框**——
形状和**地狱门一模一样**，只是把黑曜石换成平滑石：

```
俯视图（站在门前看）          侧视图
┌──┬──┐                    ▓ = 平滑石
│  │  │  ← 2 格宽的门洞       ▓
├──┼──┤                    ▓    ← 3 格高
│  │  │                      ▓
├──┼──┤                      ▓
│  │  │                      ▓▓▓
└──┴──┘
```

> 门洞也可以搭得更大（最宽 21 格、最高 21 格都支持），但**最小就是 2 宽 × 3 高**。

**必须是"平滑石"（Smooth Stone）本身**：
- ✅ `minecraft:smooth_stone`（中文：平滑石）
- ❌ 平滑石台阶（Smooth Stone Slab）
- ❌ 石头（Stone）、圆石（Cobblestone）
- ❌ 任何别的方块

### 4.2 第二步：点燃它

拿着**打火石**（Flint and Steel）对着门洞内侧的底部方块右键点火。

门洞会立刻被一层**金色传送门**填满。站进去，**大约 4 秒**后就会被传送走
（创造模式/无敌状态是瞬间）。

### 4.3 第三步：抵达空岛

你出现在空岛的落点：**坐标 (0, 100, 0)**（默认 2 格宽的门时），脚下一块平滑石平台，
正前方（+Z 方向）就是你自己的返回门。

平台的范围**由那扇门的形状决定**：与门（含左右两侧门框）等宽，并沿门的法线方向
从门平面前后各延伸 2 格。默认 2 格宽的门 → 平台 x ∈ [-1, 2]、z ∈ [0, 4]：

```
空岛俯视图（y=99 的平台 + z=2 的门；默认门内腔 2 格宽）
        x=-1  x=0  x=1  x=2
z=4      ▓    ▓    ▓    ▓
z=3      ▓    ▓    ▓    ▓
z=2      ▓    ░    ░    ▓      ← ░ = 传送门(2格宽)，▓ = 平滑石框（这一行同时是门底框）
z=1      ▓    ▓    ▓    ▓
z=0      ▓    ▓    ▓    ▓      ← ★ 你出现在这里 (0.5, 100, 0.5)
```

门更宽时平台会跟着变宽（例如内腔 8 格 → 平台 10 格宽），落点始终在平台正中。

### 4.4 第四步：返回

**走进你面前那扇门**，就会被送回**出发的那个维度、出发的那扇门旁边**（Y+1 的位置，防止卡在方块里）。

- 从主世界的门进去 → 回到主世界那扇门旁边
- 从下界的门进去 → 回到下界那扇门旁边
- 从末地的门进去 → 回到末地那扇门旁边
- 如果你是从大门进去的、又走了很远再回来，返回点会优先用你**最后一次站过的安全位置**

返回后有 **40 tick（约 2 秒）**的传送冷却，防止来回反复进出。

## 五、几条重要规则

### 5.1 空岛上的门可以拆、也可以重搭 ✅

**你永远不会因为拆掉门而被困在空岛。** 规则是这样的：

- 以落脚平台为中心、**水平 12 格、竖直 99~122 格**的范围是「可点燃区域」。
- 在区域里，你可以搭**任意形状**（宽 2~21、高 3~21）的平滑石门框并点燃它。
- 但区域内**同一时间只允许存在一扇门**：已经有门时，点新门不会有任何反应。
- 门被拆掉（或框被拆坏导致整扇门自毁）之后，区域内就又"空"了，此时重新搭门点燃即可。

所以在空岛上的实际操作是：**门坏了 → 现场搭一个新的 → 点燃 → 走人**。
（打火石与平滑石都丢进虚空了也不怕，见 5.5 的逃生命令。）

### 5.2 第一扇门复刻你的来源门 ✅

第一次有人从主世界（或下界、末地）走进空岛时，MOD 会**量下你这扇门的形状**，
然后把空岛那扇锚点门**按同样的形状与朝向重建**。

- 你在主世界搭的是默认的 2×3 小门 → 空岛也是 2×3。
- 你在主世界搭的是 5×4 的大门 → 空岛也是 5×4。
- **形状只记一次**，之后别人再从别的门进来，不会把空岛的门改掉。

### 5.3 玩家、怪物、动物、掉落物都能进 ✅

**所有实体**碰到传送门都会被传送，包括掉落物、怪物、动物。

- 玩家走玩家专属的传送路径，来源记录存在玩家能力里；
- 其它实体走另一条路径，来源记录存在实体自己的 NBT 里（跨维度会自动带过去），
  所以它们同样能**原路返回原维度、原门附近**。

> ⚠️ 好消息是你在主世界掉在门边的钻石镐会跟着进门；坏消息是**僵尸也会跟进来**。
> 空岛只有一小块平台，怪物进来后无处可去，掉下去会摔死 —— 但它们也可能站在平台上。

### 5.4 虚空掉落防护 ✅

到达点不是固定坐标，而是**随那扇门的形状动态计算**：永远落在门前那段平台的几何正中。

平台本身也不再是固定的 3×3，而是**与门等宽**（含左右两侧门框），并沿门的法线方向
**从门平面前后各延伸 2 格**。也就是说：

- 门内腔 2 格宽 → 平台 4 格宽（含两侧门框）× 5 格深；
- 门内腔 8 格宽 → 平台 10 格宽 × 5 格深。

这样无论玩家复刻来多宽的门，门框底下一定有平台承接，从门边走开也不会踩空。

但**平台之外就是虚空**，掉下去会一直落到 Y=0 以下并死亡。请小心走位。

> **从旧版本升级过来的存档**：1.0.0 版写死的是一块以原点为中心的 3×3 平台
> （x,z ∈ [-1,1]），而现在的平台是 x ∈ [-1,2]、z ∈ [0,4]。旧平台靠门背后的那一行
> （z = -1 的 3 格）落在新平台之外，升级后已经被自动清理，不会留下悬空石台。
> 这条清理只删「旧 3×3 范围之内、新平台范围之外、且当前确实是平滑石」的格子，
> 你在空岛上自己搭的方块不受影响。

### 5.5 实在出不去时的逃生命令 ✅

如果你把打火石和平滑石都丢进了虚空，可以执行：

```
/dimensionhome home
```

它只在空岛维度内有效，会立刻把你送回**原来那个维度、原来那扇门旁边**，效果与走进返回门完全一样。

> 这条命令是**我额外加的**（原始需求里没有）。理由：空岛是纯虚空、没有任何资源，
> 一旦玩家把打火石和平滑石都丢下去，就没有任何游戏内手段能离开，只能删档。
> 这条命令是最后一道保险，正常玩不会用到。

### 5.6 死亡后返回信息保留 ✅

你记录的"来源维度 + 来源门位置"存在玩家能力里，并已处理死亡克隆，
所以**死亡重生后，从空岛返回依然能回到原来的门**。

## 七、内置自检命令

本 MOD 带了三条验收命令，用于**可复现地**核对所有需求，不必靠肉眼观察：

### `/dimensionhome selftest` — 维度 / 地标 / 点燃规则自检（40 项）

逐条核对维度类型参数、纯虚空、地标几何（含**平台与门等宽**与**动态落点**）、
**区域内可点燃 / 区域外禁燃 / 唯一门 / 首门复刻**、CPA 注册与染色：

```
===== 维度之家 自检报告 =====
[通过] 空岛维度已注册并可加载  [ServerLevel[world]]
[通过] coordinateScale = 1.0（1:1 坐标，非文档的下界式 8.0）  [1.0]
[通过] hasSkyLight = true（有天空光）  [true]
[通过] hasFixedTime = false（昼夜交替，fixed_time 留空）  [fixedTime=OptionalLong.empty]
[通过] hasRaids = false（不触发袭击）  [false]
[通过] bedWorks = true（床可用）  [true]
[通过] ultraWarm = false  [false]
[通过] hasCeiling = false  [false]
[通过] minY = 0  [0]
[通过] height = 256  [256]
[通过] logicalHeight = 256  [256]
[通过] 区块生成器是 VoidChunkGenerator（纯虚空）  [VoidChunkGenerator]
[通过] 远离地标处不生成任何地形（采样 25 点全为空气）  [非空气方块数=0]
[通过] 锚点门形状合法（内腔 轴向=X，内腔 2x3）  [轴向=X，内腔 2x3]
[通过] 落脚平台与门等宽并前后各延伸 2 格（4 宽 x 5 深，共 20 格平滑石，y=99）
[通过] 旧 3x3 平台的残留已清理（门后无孤立方块）  [残留 0 格]
[通过] 落点 BlockPos{x=0, y=100, z=0} 位于可站立区域内  [BlockPos{x=0, y=100, z=0}]
```

### 空岛地形

- 生成器：`dimensionhome:void_generator`（自定义 `VoidChunkGenerator`）
- 行为：**不生成任何方块**，只做区块初始化（高度图与群系填充），群系分布复用主世界的 `multi_noise` 预设
- 空岛里唯一的方块，来自地标建造器 `SkyLandmarkBuilder`（服务器启动时执行一次）

### 传送门

- 框架方块：`minecraft:smooth_stone`（平滑石）
- 点燃方式：打火石（`PortalIgnitionSource.FIRE`）
- 染色：`tintColor(255, 215, 0)` = **金色 `#FFD700`**
  （CPA 把它注册成门方块的 block color，模型三个朝向都用 `tintindex: 4` 引用它；
  **这个值同时决定门方块本身、传送时的屏幕蒙版、以及门口粒子三处的颜色**。
  门贴图是一张 16×512 的 32 帧灰阶动画、平均像素约 200/255 ≈ 0.783，
  相乘后实机呈现的成色约为 **`#C7A800` 琥珀金**。）
- 注册的目标维度：`dimensionhome:sky_dimension`
- 框架检测器：`dimensionhome:sky_zone`（自定义；空岛内按「区域 + 唯一门」放行，其它维度不受影响）
- 可点燃区域：`x, z ∈ [-12, 12]`，`y ∈ [99, 122]`
- 传送接管：通过 CPA 的 `registerBeforeTPEvent` 返回 `CANCEL_TP` 完全接管，
  再用 `ServerPlayer.teleportTo(...)` 精确落点
- 首门形状记录：存在空岛维度的 `SavedData`（`dimensionhome_gate`）里，只写一次

## 九、常见问题

**Q：点燃了但门没出现？**
A：检查框架方块。必须是**平滑石**（`minecraft:smooth_stone`），不是石头、圆石、也不是平滑石台阶。
另外门洞最小要 **2 格宽 × 3 格高**。

**Q：进不去空岛，聊天栏提示"维度之家：空岛维度未加载"？**
A：数据包没加载成功。确认 jar 内有 `data/dimensionhome/dimension/sky_dimension.json`
与 `data/dimensionhome/dimension_type/sky_type.json` 两个文件；
同时确认没有装会覆盖 `dimensionhome` 命名空间的其他数据包。

**Q：客户端/服务器启动崩溃，提示 `Missing or unsupported mandatory dependencies`？**

A：**最常见的坑：只放了一个 jar。** 本 MOD 和前置必须**同时**在 `mods\` 里。

崩溃报告里会出现这样的字样（`crash-reports\crash-*-fml.txt`）：

```
[main/ERROR] [ModSorter/LOADING]: Missing or unsupported mandatory dependencies:
	Mod ID: 'cpapireforged', Requested by: 'dimensionhome', Expected range: '[1.0.2,)', Actual version: '[MISSING]'

net.minecraftforge.fml.ModLoadingException: Mod dimensionhome requires cpapireforged 1.0.2 or above
	Currently, cpapireforged is not installed
-- MOD dimensionhome --
	Mod File: .../mods/dimensionhome-1.0.0.jar
```

处理办法：

1. 打开 `mods\` 文件夹，确认里面**两个 jar 都在**：
   - `dimensionhome-1.0.0.jar`
   - `customportalapi-reforged-1.0.2.jar`
2. 缺哪个补哪个，然后**完全重启游戏**（崩溃过一次后必须重启，回到主菜单无效）。
3. 重启后在 Mods 列表里应同时看到 **Dimension Home** 与 **Custom Portal API ReForged**。

> 💡 记不住的话：**这个 MOD 不能单独装**。就像机械动力要前置 Flywheel 一样，
> 少一个就起不来，而且报的是"missing dependency"而不是本 MOD 的名字，容易被误会是 MOD 本身有问题。

**Q：在空岛里点火没反应？**
A：分两种情况：

1. **离平台太远**（水平超过 12 格）→ 区域之外不允许点燃，这是刻意的。
2. **区域内已经有一扇门了** → 同一时间只允许一扇，先把旧门拆掉再点。

区域内、又没有门的时候，点火一定会成功。

**Q：从下界进去，返回却回到了主世界？**
A：正常行为应该回到下界。如果出现这种情况，请执行 `/dimensionhome tptest` 并把输出反馈。
（正常情况下来源维度会被记录并正确返回。）

**Q：掉进虚空了怎么办？**
A：平台只有门前那一小块（与门等宽、前后各延伸 2 格），走位小心。掉下去会死亡重生——重生后你仍在原来的维度，
重新搭门进去即可（死亡克隆已处理，来源记录不会丢）。

**Q：能在空岛建房子吗？**
A：可以。空岛是虚空，但你可以自由放置任何方块。只要别把唯一那扇门拆了就行。

**Q：拆了空岛那扇门会怎样？会被困住吗？**
A：**不会被困。** 门方块本身无法被破坏（和地狱门一样），但**拆掉平滑石外框会让门消失**。
门消失后就相当于区域内"空"了，你只要**在平台附近 12 格内重新搭一个平滑石门框、用打火石点燃**，
门就会重新出现（形状随你搭）。如果连打火石和平滑石都丢了，用 `/dimensionhome home` 逃生。

**Q：空岛那扇门的形状为什么和我搭的不一样？**
A：空岛第一扇门会**复刻第一次有人进门时那扇来源门的形状**，这是刻意的设计。
形状只记一次，之后别人从别的门进来不会改它。

## 十、从源码重新构建

```bat
git clone https://github.com/GNX001/dimensionhome.git
cd dimensionhome
set JAVA_HOME=C:\Program Files\Java\jdk-17.0.2
gradlew.bat build
```

产物在 `build\libs\dimensionhome-1.0.0.jar`。

**改完代码后重新装进游戏**，只要把新 jar 覆盖到游戏的 `mods\` 目录：

```bat
copy /Y "build\libs\dimensionhome-1.0.0.jar" "<你的游戏目录>\mods\"
```

> 覆盖后必须**完全重启游戏**（回到主菜单无效）。前置 `customportalapi-reforged-1.0.2.jar` 不用重装。

> 构建环境要求 **JDK 17**。首次构建会下载 Forge/Minecraft 依赖，需要网络。
> `gradle.properties` 里的 `org.gradle.daemon=false` **不要改成 true**——
> ForgeGradle 在守护进程模式下会因工具链服务提前关闭而构建失败。

开发环境运行（需要 IDE 或命令行）：

```bat
gradlew.bat runClient    :: 启动带 MOD 的客户端
gradlew.bat runServer    :: 启动带 MOD 的服务器
```
